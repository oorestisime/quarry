Quarry adds typed query composition to your existing `@clickhouse/client`.
Table names, filters, and selected columns determine the inputs you can pass
and the result rows you receive.

## Start with a working example

[Run the quickstart](/docs/guides/getting-started) to start a seeded ClickHouse
instance, generate TypeScript types, and query a working analytics endpoint.
You will see the expected JSON and the SQL that produced it at each step.

**Already have ClickHouse?** [Add Quarry to your project](/docs/guides/existing-project)
and reuse your connection. **Just exploring?** [Try the playground](/playground)
to inspect SQL without a database.

## Build something useful

| I want to… | Start with |
| --- | --- |
| Plot event counts by day | [Daily activity](/docs/recipes/daily-activity) |
| Find each user's latest event | [Latest event per user](/docs/recipes/latest-event) |
| Add optional dashboard filters | [Optional filters](/docs/recipes/optional-filters) |
| Page through grouped results | [Pagination](/docs/recipes/pagination) |
| Export rows without buffering everything | [Streaming export](/docs/recipes/streaming-export) |

Every recipe uses the quickstart's schema and seed data. Its query code comes
from the runnable example, and CI checks its SQL and expected results against
ClickHouse.

## Know which version you are using

Quarry is pre-1.0. Minor releases may change the API with a changelog entry;
patch releases preserve it. These docs follow development, which currently
includes changes beyond npm 0.9.1. [Release guidance](/docs/releases) identifies
the differences and explains how to run matching examples.
